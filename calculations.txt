PAIRED LIFECYCLE LATENCY ANALYSIS

1. Build the paired dataset

For each operation, compare platform A with platform B in the same
benchmark round i. A is the numerator and B is the reference.

  L[A,i] = inputPreparationMs[A,i]
           + confirmationMs[A,i]
           + postReceiptToValidatedPlaintextMs[A,i]

Use zero for absent input preparation. The two other terms measure
submission to observed receipt, then observed receipt to validated
plaintext. Latencies are in milliseconds.

Keep measured rounds where both primary observations succeeded. This
gives n = 50 pairs.
Keep the original and continuation segments separate for resampling.

2. Calculate the numbers shown in the table

  Arithmetic mean latency for A = sum_i L[A,i] / n
  Arithmetic mean latency for B = sum_i L[B,i] / n

Both arithmetic means use the same selected pairs for their row.
Consequently the baseline mean for add can differ across comparisons.

  r[i]  = L[A,i] / L[B,i]
  d[i]  = ln(r[i])
  d_bar = sum_i d[i] / n
  R     = exp(d_bar) = (product_i r[i])^(1/n)
  Overhead (%) = 100 * (R - 1)

R is the geometric mean of the paired ratios. For example, ratios of
2 and 0.5 yield log ratios of +ln(2) and -ln(2). Their geometric mean
is 1. Dividing the arithmetic mean latency columns is a different
calculation. R > 1 means A takes longer on the paired ratio metric.

  H0: E[d] = 0, equivalent to exp(E[d]) = 1.
  H1: E[d] differs from 0, allowing either direction.

3. Generate the bootstrap replicates

A replicate is a new sample assembled from the measured log ratios.
For a segment s of size n_s, label its log ratios d[s,0] through
d[s,n_s-1]. Let ell be the chosen block length.

  Effective block length in segment s = l_s = min(ell, n_s)
  Number of sampled blocks = ceil(n_s / l_s)

For each block draw a start J uniformly from 0 through n_s-1, with
replacement. The block contains:

  d[s,J], d[s,(J+1) mod n_s], ..., d[s,(J+l_s-1) mod n_s]

Modulo indexing wraps the block within its own segment. Concatenate
the blocks and keep the first n_s entries. Repeat independently for
the other segment, preserving its sample count too.

  d_star_bar[b] = sum_s sum_j d_star[b,s,j] / sum_s n_s

Example with six observations and blocks of length three. If both
draws start at index 1, the indices selected are [1,2,3,1,2,3].
Every index still represents its original paired ratio. Blocks keep
nearby observations together to retain some short-range dependence.

The primary setting is ell = 3 and B = 199,999 replicates for each
comparison. B is the number of random resamples of the existing data.
Repeating the computation reduces Monte Carlo variation. The amount
of benchmark data remains n pairs.

4. Center the replicates and calculate the confidence interval

  e[b] = d_star_bar[b] - d_bar

Each e[b] measures how far a resampled estimate moved from the
observed estimate. Let Q(p) be the p-quantile of these errors,
computed by linear interpolation between adjacent sorted values.
For B sorted values, the zero-based interpolation index is (B-1)*p.

  Basic 95% CI on log scale = [d_bar - Q(0.975), d_bar - Q(0.025)]
  Basic 95% CI on ratio scale = [exp(lower log limit), exp(upper log limit)]

The subtraction reverses the error quantiles because the calculation
uses the estimated errors to infer where the underlying value could
lie. Each interval has pointwise 95% coverage under the method's
assumptions. The intervals are reported individually across rows.

The script also records a bootstrap standard error on the log scale:

  SE_boot = sqrt(sum_b (d_star_bar[b] - average_b(d_star_bar[b]))^2 / (B-1))

5. Calculate the raw two-sided p-value

Compare the observed log ratio d_bar with the centered errors, which
approximate the variation of the estimate around a null value of zero.

  N_lower = count of b with e[b] <= d_bar
  N_upper = count of b with e[b] >= d_bar
  p_raw   = min(1, 2 * (min(N_lower, N_upper) + 1) / (B + 1))

Doubling the smaller tail allows for departures in either direction.
The +1 correction gives a minimum raw p-value of 2/(B+1) = 0.00001.
That minimum is the numerical resolution of this calculation.

6. Adjust across all 15 comparisons

There are five operations and three contrasts per operation. The
contrasts are Zama/baseline, Fhenix/baseline, and Zama/Fhenix.

Sort the raw p-values p_(1) <= ... <= p_(m), where m = 15.
For each rank k, compute:

  weighted_p[k] = (m - k + 1) * p_(k)
  p_Holm[k] = min(1, max(weighted_p[1], ..., weighted_p[k]))

Return the adjusted p-values to their original rows. The script
rejects H0 when p_Holm < 0.05. Holm controls the chance of at least one
false rejection across the family at the chosen level, subject to
valid raw p-values. The reported confidence intervals remain pointwise.

7. Check sensitivity to block length

Repeat steps 3 through 6 with ell = 1, 2, and 5 as well as the primary
ell = 3. Length 1 draws individual paired observations within each
segment. Compare the confidence intervals and adjusted decisions
across lengths. The decisions in these data agree across all four
settings. The bootstrap relies on approximate within-segment
stationarity and sufficiently weak temporal dependence.

8. Worked example from the paper

Operation mean, platform A = Zama, platform B = Fhenix, n = 50.

  R = 1.023271
  d_bar = ln(1.023271) ~= 0.0230
  Overhead = 100 * (1.023271 - 1) ~= +2.33%
  Pointwise 95% CI for R = [0.990534, 1.055157]
  Raw p-value = 0.15935
  Holm-adjusted p-value = 0.15935

The estimated client lifecycle latency was 2.33% higher for Zama on
this operation. The interval includes a ratio of 1 and the adjusted
p-value exceeds 0.05, so the comparison is inconclusive at that level.

For rows at the raw p-value floor, Holm yielded 0.00015. The tables
display adjusted p-values below 0.001 as <0.001. The mean latency
columns are rounded to whole milliseconds for display.
